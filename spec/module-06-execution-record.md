# M06 执行记录 Spec

> 状态：待实现 · 范围依据 [mvp1-scope.md](mvp1-scope.md) v1.0 第 3、4、5 节及 `context.md` 5.1、5.2、12 节
> AC 编号 `AC-06-NN`；写法约定与演示数据见 [mvp1-scope.md](mvp1-scope.md) 第 6、8 节。

## 1. 目标与边界

**做**：学员提交三类记录——训练完成情况与感受、餐次与餐食文字、体重；教练查看自己负责学员的记录；记录关联到当时已发布的计划与建议版本。

**不做**：餐食照片上传（待确认，本版不纳入）、拍照识别、热量估算、穿戴设备同步、自动填报、体重趋势图绘制（M08）、反馈内容本身（M07）。

**注意**：「餐食照片上传」「拍照识别」「热量估算」是三种不同能力；前一项待确认，后两项在 `context.md` 5.2 中明确不纳入 MVP1，不得捆绑讨论或顺带实现。

## 2. 关键规则

- 记录必须关联到学员本人**已发布**的训练计划或饮食建议；不能针对草稿提交。
- 记录一旦提交，其关联的计划/建议版本固定，后续发布新版本不改变既有记录内容（历史一致性）。
- 每类记录的最小必填项见各 AC；缺项不得产生半成品记录。
- 教练只能查看负责学员的记录；管理员不默认可查看私人记录。

## 3. 角色与权限

| 角色 | 允许 | 拒绝 |
| --- | --- | --- |
| 学员 | 提交/查看自己的三类记录 | 提交他人记录、修改教练反馈 |
| 负责教练 | 查看负责学员的记录（供反馈） | 修改或代提交学员记录、查看无关系学员记录 |
| 管理员 | 无 | 查看私人记录正文、体重或反馈 |

## 4. 前置条件

C-001 与 T-001 关系生效；P-001 为已发布训练计划，N-002 为已发布饮食建议，D-001 为 `draft` 草稿；R-001 为 T-001 针对 P-001 的训练执行记录。

## 5. 验收标准

**AC-06-01 `[正常流]` 提交训练完成情况**
**Given** T-001 已登录，P-001 已发布且含 ACT-001 / 3 组 / 10 次
**When** T-001 针对 P-001 提交"完成 3 组中的 2 组、每组 10 次，感受：偏累"并保存
**Then** 产生一条关联 P-001 的训练执行记录，且记录包含完成情况与感受文本，且以结构化字段保存"要求组数 3、完成组数 2"（供 M08 计算完成率），且 T-001 与 C-001 均可查看到该记录，且记录中保存了 P-001 当时的动作与组次

**AC-06-02 `[正常流]` 提交餐食文字记录**
**Given** T-001 已登录，N-002 已发布
**When** T-001 选择餐次"午餐"并提交餐食文字"鸡胸肉、米饭、青菜"
**Then** 产生一条含餐次与文字内容的餐食记录，且不含任何照片字段或热量数值，且 C-001 可查看到该记录

**AC-06-03 `[正常流]` 提交体重记录**
**Given** T-001 已登录
**When** T-001 提交日期 2026-11-10 与体重数值 62.5kg
**Then** 产生一条含日期与数值的体重记录，且 T-001 与 C-001 可查询到该记录，且重复查询返回值一致

**AC-06-04 `[异常流]` 针对草稿提交**
**Given** T-001 已登录，存在 `draft` 状态的 D-001
**When** T-001 绕过界面直接请求针对 D-001 提交训练执行记录
**Then** 服务端拒绝并提示目标内容未发布，且不产生记录，且不返回 D-001 的内容

**AC-06-05 `[权限]` 学员代他人提交**
**Given** T-001 已登录
**When** T-001 绕过界面直接请求以 T-002 身份提交一条训练执行记录
**Then** 服务端返回拒绝（权限不足），且不产生任何记录，且响应中不含 T-002 的数据

**AC-06-06 `[权限]` 非负责教练查看记录**
**Given** C-002 已登录且与 T-001 无生效指导关系
**When** C-002 绕过界面直接请求 R-001
**Then** 服务端返回拒绝（权限不足），且响应中不含完成情况、感受、餐食或体重字段

**AC-06-07 `[异常流]` 必填缺失**
**Given** T-001 已登录
**When** T-001 提交训练执行记录时未选择关联计划，或提交餐食记录时餐次与文字均为空
**Then** 提交被拒绝，且提示明确指出缺失的项，且不产生记录

**AC-06-08 `[历史一致性]` 新计划不改变旧记录**
**Given** R-001 关联 P-001（ACT-001 / 3 组 / 10 次）
**When** C-001 发布下一周期 P-002（4 组 / 8 次），随后查询 R-001
**Then** R-001 仍关联并展示 P-001 当时的 3 组 / 10 次，且 R-001 的完成情况与感受文本不变

**AC-06-09 `[正常流]` 教练查看负责学员记录**
**Given** C-001 负责 T-001，存在 R-001 及 T-001 的餐食、体重记录
**When** C-001 查询 T-001 的执行记录
**Then** 返回三类记录且按关联计划/建议可追溯，且不包含其他学员的记录，且该视图可作为 M07 反馈的入口

## 6. 与其他模块的依赖

- 依赖 M01（服务端权限）、M02（生效指导关系）、M03（已发布计划及版本）、M05（已发布饮食建议）。
- 被依赖：M07 的提问与反馈围绕本模块的记录展开；M08 用本模块数据计算完成率与体重变化。
- 与 M05 的边界：本模块只存"学员提交了什么"，不存饮食建议内容本身。

## 7. 待确认项

- 餐食照片是否纳入第一版：当前不纳入；若纳入需走 mvp1-scope.md 第 7 节变更流程并新增 AC（含存储、隐私与展示范围）。
- 本版已固定"要求组数 / 完成组数"两个结构化字段（M08 的完成率计算依赖，见 AC-06-01）；是否细化到逐动作勾选、体重单位与日期规则仍待确认，不写入本版 AC。

## 8. 不在本模块范围

进度计算与图表（M08）、反馈文本与回复（M07）、计划发布（M03）、饮食建议内容（M05）、照片存储与识别、热量数值。
