# Spike 02：服务端权限校验探针

> 状态：**待执行**（本次仅起草计划，未执行） · 日期：2026-11-11 · 关联 [`adr/001-technology-stack.md`](../adr/001-technology-stack.md) 方案 B
> 验证目标：M01 的 AC-01-05 / 06 / 07、M09 的 AC-09-08
> 执行需团队授权，在独立验证环境进行；**不写入 `src/`**。本周不写业务代码，本文件是计划而非已执行结果。

## 1. 目的

在 Spring Boot 3 + Spring Security 上验证"学员/非负责教练/管理员绕过界面直接请求业务数据时，由服务端拒绝"，确认权限不是只靠前端隐藏按钮。这是 `spec/mvp1-scope.md` 第 3.1 节"权限由服务端判定"的关键证据。

## 2. 前置条件

- Spring Boot 3.x + Spring Security 最小探针环境（独立目录，不写入项目 `src/`）。
- 虚构账号：T-001（学员）、C-001（负责 T-001）、C-002（与 T-001 无指导关系）、A-001（管理员）。
- 指导关系 C-001↔T-001 生效；R-001 为 T-001 的私人执行记录。

## 3. 输入（用例集）

| 用例 | 角色 | 直接请求 | 期望 |
| --- | --- | --- | --- |
| S02-1 | T-001 学员 | 确认并发布训练计划（教练功能） | 服务端拒绝 |
| S02-2 | C-002 非负责教练 | T-001 的档案与执行记录 | 服务端拒绝 |
| S02-3 | A-001 管理员 | R-001 执行记录正文 | 服务端拒绝 |
| S02-4 | 未认证 | 任一需认证业务数据 | 服务端拒绝 |

## 4. 执行步骤

1. 实现 JWT 签发与校验过滤器，会话携带角色与身份。
2. 配置方法级权限（`@PreAuthorize`）控制角色。
3. 实现数据级权限：查询档案/记录前校验"负责教练"关系。
4. 对每个用例，绕过前端、直接用 HTTP 调对应接口，记录状态码与响应体。
5. 对照期望判定，并确认响应不含任何业务字段（不止是不渲染界面）。

## 6. 判定标准

- **通过**：四个用例均由服务端返回拒绝（403/401），响应不含业务字段，且权限判定发生在服务端而非仅前端隐藏。
- **失败**：任一用例返回了业务数据，或权限只靠前端按钮隐藏。

## 7. 结论边界

- 能证明：方案 B 能实现"角色 + 指导关系"双层服务端权限，满足 AC-01-05/06/07 与 AC-09-08。
- 不能证明：前端交互、会话有效期、登录失败次数限制（M01 第 7 节待确认项）。
- 不代替 M01、M09 的完整业务验收。

## 8. 风险与替代

- 数据级权限散落在多处易遗漏：改用统一拦截器或 Aspect，或借助 Spring Security 的方法级 + 自定义 Voter 集中判定。
- 性能影响：指导关系校验需缓存或预加载；记录探针中的查询代价。
